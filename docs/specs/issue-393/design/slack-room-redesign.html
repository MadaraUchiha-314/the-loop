Chips → requirements (docs/specs/issue-393/requirements.md)

1R1 — a channel name resolves wherever the bot can already speak (bot-membership listing first; a truncated workspace listing never reads as “no such channel”).
2R2.5 — a refused act is explained where it was attempted, with the remedy, not only in the daemon log.
3R3 — the session inherits the daemon’s config path, so its questions and summaries actually reach the room (the plumbing behind every session-voiced message here).
4R4 — the first authorized answer advances the gate; the ✅ never lies.
6R6 — one message per meaningful moment: no started/completed pairs, one announcement per gate, one per-phase progress message edited in place (owner decision: per phase).
7R7 — no machine header; the emoji and the sentence lead.
8R8 — the gate message carries the agent’s 2–3 sentence summary and what it is least sure of; the PR gate names PR, diffstat and link.
9R9 — phase selection is in-message Block Kit checkboxes + the outer-loop question in the same message, submitting the same signed execute (owner decision: checkboxes, not a modal); typing skip <phase> works for connectors without buttons.
10R10 — acknowledgements are thread replies under the message they answer.
11R11 — first person, present tense, one state emoji, no robot-face signature, no policy boilerplate; one closing message with the outcome.
12R12 — the session’s own words are the room’s content; templates yield to them.
